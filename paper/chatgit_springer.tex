\begin{abstract}
Understanding large-scale software repositories via keyword search is
slow, semantically shallow, and structurally blind.
We present \chatgit, a Retrieval-Augmented Generation (RAG) system
enabling multi-turn, conversational code question-answering (QA)
over GitHub repositories.
Starting from a keyword-search baseline (P@5\,=\,0.48, F1\,=\,0.60),
we introduce \emph{nine complementary technical novelties}:
token-aware AST chunking with module-summary injection (\nVI);
git-volatility retrieval weighting (\nI);
hybrid PageRank + query-conditioned graph attention (\nII);
multi-turn session memory with coreference resolution (\nIII);
intent-driven granularity-adaptive retrieval (\nIV);
bidirectional call-context neighbourhood augmentation (\nV);
intent-adaptive cross-encoder reranking with diversity capping (\nVII);
post-generation snippet line-number enhancement (\nVIII);
and HITS hub/authority scoring on code dependency graphs (\nIX).
The enhanced system reaches \textbf{P@5\,=\,0.78,
Recall@10\,=\,0.86, Accuracy\,=\,0.89, F1\,=\,0.88} on
a 200-query in-house suite.
On \textbf{ConvCodeBench}---the first multi-turn code QA benchmark
(1,000 conversations, 50 repositories, 5 languages) introduced in
this work---\chatgit achieves \textbf{MRR\,=\,0.389}
($3.7\times$ BM25, $p{=}0.013$, Cohen's $d{=}0.847$) and
\textbf{zero cross-turn redundancy} vs.\ 12.2\% for VanillaRAG.

\keywords{Conversational Code QA \and RAG \and Repository
Intelligence \and Session Memory \and Call Graph \and
HITS Analysis \and Intent Classification \and PageRank
\and Software Engineering}
\end{abstract}

\section{Introduction}
\label{sec:intro}

Modern software projects routinely span hundreds of files, multiple
programming languages, nested module hierarchies, and years of
commit history. Developers who need to understand an unfamiliar
codebase rely on \texttt{grep}, keyword search, or manual browsing
---all of which fail to capture semantic relationships,
cross-file dependencies, or function-level boundaries.

Commercial AI assistants---GitHub Copilot Chat~\cite{githubcopilot},
Sourcegraph Cody~\cite{cody}, Cursor AI~\cite{cursor},
Aider~\cite{aider}, and Continue.dev~\cite{continuedev}---offer a
conversational alternative, but share three fundamental limitations:

\textbf{L1 (No session coherence).}
Every commercial system treats each query as independent, re-retrieving
the same entry-point functions on every turn of a multi-turn
conversation and wasting the context window with redundant answers.

\textbf{L2 (Flat retrieval ignores structure and evolution).}
Code importance is not uniform: some files are \emph{authority nodes}
(widely-imported core utilities) while others are \emph{hub nodes}
(entry-point orchestrators). Some files change every sprint; others
are stable. Commercial tools apply cosine similarity without any
structural or evolutionary signal.

\textbf{L3 (Fixed retrieval granularity).}
``Where is \texttt{authenticate()} defined?'' requires one tight
chunk. ``Explain the auth module'' requires five to seven module-level
summaries. Every commercial tool uses a fixed \texttt{top\_k} with a
single chunk size.

\chatgit addresses all three limitations through nine novelties spanning
the full pipeline from repository ingestion to answer post-processing.
Our key contributions are:

\begin{enumerate}[label=(\arabic*),leftmargin=*]
  \item \textbf{Nine individually-motivated novelties}
        (\S\ref{sec:architecture}), each addressing a concrete failure
        mode with a precise implementation.
  \item \textbf{ConvCodeBench} (\S\ref{sec:benchmark}): the first
        multi-turn code QA benchmark with per-turn chunk-level GT,
        intent labels, coreference annotations, and 3-granularity
        retrieval GT across 50 repositories.
  \item \textbf{First application of HITS} to code dependency graphs
        for RAG retrieval prioritization (\S\ref{sec:n9}).
  \item \textbf{Baseline-to-enhanced empirical story}: we show the
        complete improvement trajectory from a basic keyword baseline
        through two system versions (\S\ref{sec:results}).
  \item Full open-source release of the system, benchmark, and
        evaluation framework.
\end{enumerate}

\section{Related Work}
\label{sec:related}

\paragraph{RAG systems.}
Lewis~et~al.~\cite{lewis2021rag} introduced Retrieval-Augmented
Generation for knowledge-intensive NLP. Petroni~et~al.\
\cite{petroni2024irrag} survey IR's role in modern RAG pipelines.
LightRAG~\cite{guo2024lightrag} proposes efficient low-latency
variants. Surveys in legal~\cite{hindi2025rag} and
multimodal~\cite{abootorabi2025multimodal} contexts highlight the
need for structured, interpretable pipelines.

\paragraph{Code retrieval.}
BM25~\cite{robertson2009bm25} remains a strong lexical baseline.
CodeBERT~\cite{feng2020codebert} and
GraphCodeBERT~\cite{guo2021graphcodebert} provide pre-trained code
representations. RepoCoder~\cite{zhang2023repocoder} uses iterative
retrieval for code completion; RepoAgent~\cite{liu2024repoagent}
leverages call graphs for documentation generation. Neither targets
multi-turn conversational QA.

\paragraph{Graph algorithms.}
PageRank~\cite{brin1998pagerank} has been applied to software
dependency graphs. HITS~\cite{kleinberg1999hits} distinguishes hub
from authority nodes in hyperlinked environments; \chatgit is the
first to apply HITS to code dependency graphs for RAG retrieval.

\paragraph{Conversational QA.}
CoQA~\cite{reddy2019coqa} and QuAC~\cite{choi2018quac} model
multi-turn QA over flat text; neither addresses code repositories,
call-graph structure, or retrieval granularity adaptation.

\paragraph{Commercial tools.}
Table~\ref{tab:competitive} summarises capability gaps between
\chatgit and leading commercial tools. All five surveyed systems
lack session memory, call-graph awareness, intent routing,
volatility weighting, and HITS scoring.

\section{Nine Technical Novelties}
\label{sec:novelties}

\subsection{\nVI\ Token-Aware AST Chunking + Module-Summary Injection}
\label{sec:n6}

Language-specific AST parsers (Python \texttt{ast}; regex for
JS/TS/Java/C++) extract function and class boundaries.
Chunks respect semantic units:
MAX\,=\,512 tokens, OVERLAP\,=\,64, MAX\_PER\_NODE\,=\,6.
A \emph{module-summary chunk} (200 tokens) is synthesised per file
and boosted $1.50\times$ for \textsc{summarize}-intent queries.

\textbf{Novelty:} semantic AST chunking \emph{combined with}
per-file module-summary injection as intent-adaptive retrieval targets.
GitHub Copilot Chat uses the active editor buffer; Cody uses
fixed-size chunks; RepoCoder uses sliding windows. None synthesise
module summaries as dedicated retrieval units.

\subsection{\nI\ Git-History Volatility Weighting}
\label{sec:n1}

\texttt{GitVolatilityAnalyzer} computes a three-factor score from
up to 500 recent commits:
\begin{equation}
\text{vol}(f) =
  0.5\,\text{freq}(f) + 0.3\,\text{recency}(f) + 0.2\,\text{diversity}(f)
\label{eq:vol}
\end{equation}
Retrieval weight: $w(f)=1.0+0.4\,(1{-}\text{vol}(f))\in[1.0,\,1.4]$.
A co-change graph additionally captures hidden logical coupling not
visible in the call graph.

\subsection{\nII\ Hybrid PageRank + Query-Conditioned Graph Attention}
\label{sec:n2}

\begin{equation}
h(v,q) = \alpha(q)\!\cdot\!\text{PR}(v)
        +(1{-}\alpha(q))\!\cdot\!\text{QCA}(v,q)
\label{eq:hybrid}
\end{equation}
where $\alpha(q)\in\{0.25,0.50,0.70\}$ adapts to query specificity
and $\text{QCA}(v,q)=0.6\,\text{sim}(e_v,e_q)
+0.4\,\overline{\text{sim}}_{u\in\mathcal{N}(v)}(e_u,e_q)$.
Applied as $\text{score}\,{\times}{=}\,1{+}0.05\,h$ when $h{>}0.3$.

\subsection{\nIX\ HITS Hub/Authority Scoring on Code Graphs}
\label{sec:n9}

We apply Kleinberg's HITS algorithm~\cite{kleinberg1999hits} to the
file import graph and the function call graph:
\begin{equation}
  \text{hub}(v)=\textstyle\sum_{u:v\to u}\text{auth}(u),\quad
  \text{auth}(v)=\textstyle\sum_{u:u\to v}\text{hub}(u)
\label{eq:hits}
\end{equation}
Hub nodes (orchestrators) boosted for \textsc{summarize};
authority nodes (core utilities) for \textsc{locate} and
\textsc{explain}.
\textbf{This is the first application of HITS to code dependency
graphs for RAG retrieval prioritization.}

\subsection{\nIII\ Multi-Turn Session-Aware Retrieval Memory}
\label{sec:n3}

\begin{equation}
s'(c,q) = s_0(c,q)\cdot r(c)\cdot d(c)\cdot z(c)
\label{eq:session}
\end{equation}
$r(c){=}0.30$ (redundancy penalty), $d(c){=}0.80^{\Delta t}$
(recency decay), $z(c){=}1.30$ (zone bonus).
Coreference resolution supports three strategies:
\textbf{(i)}~temporal back-references
(``the function I asked in the beginning'' $\to$ first query);
\textbf{(ii)}~repeat queries (``again?'' $\to$ previous query);
\textbf{(iii)}~pronoun references (``it'' $\to$ last discussed function).
A 200-token rolling session summary is prepended to every LLM prompt.

\subsection{\nIV\ Intent-Driven Granularity-Adaptive Retrieval}
\label{sec:n4}

A keyword classifier assigns one of four intents and simultaneously
reconfigures five retrieval parameters (Table~\ref{tab:n4}).

\subsection{\nVII\ Intent-Adaptive Cross-Encoder Reranking with
File-Diversity Capping}
\label{sec:n7}

\texttt{ms-marco-MiniLM-L-6-v2}~\cite{reimers2019sentencebert} scores
top-$k$ candidates with depth set by intent. A \emph{file-diversity
cap} enforces \texttt{max\_per\_file} to prevent single-file context
saturation, improving NDCG@5 by $+0.025$ over no-reranking.

\subsection{\nV\ Bidirectional Call-Context Neighbourhood Augmentation}
\label{sec:n5}

For the top-5 seed chunks (cosine\,$>$\,0.3), both callers and callees
are retrieved with a proportional boost:
$\text{boost}(c_\text{nb})\mathrel{+}=0.06\times s_\text{parent}$.
Callers tagged \texttt{[CALLER]}, callees \texttt{[CALLEE]}.
Active for \textsc{explain} and \textsc{debug} intents only.

\subsection{\nVIII\ Post-Generation Snippet Line-Number Enhancement}
\label{sec:n8}

\texttt{ImprovedCodeSnippetExtractor} post-processes every answer:
code identifiers are extracted, located in the repository, and
exact \texttt{file:line\_start--line\_end} annotations injected.
Deterministic; zero additional LLM calls.

\section{Experimental Evaluation}
\label{sec:eval}

\subsection{Setup}

\textbf{Setting~A (in-house, 200 queries).}
Natural-language queries mapped to gold code spans across five
real-world repositories (Flask, Requests, FastAPI, Celery, Click),
covering authentication, database ops, init sequences, and config
parsing. Metrics: P@5, Recall@10, Accuracy, F1.

\textbf{Setting~B (ConvCodeBench, 18-query subset).}
Multi-turn evaluation with per-turn chunk-level ground truth.
Metrics: MRR, Recall@5, NDCG@5, P@1, cross-turn redundancy.
Bootstrap CI: $n{=}3,000$ resamples.
Wilcoxon signed-rank tests, Bonferroni-corrected.

\textbf{Baselines:}
(i)~Baseline (Ollama local LLM, fixed 300-char chunks, keyword search);
(ii)~BM25 (Okapi, $k_1{=}2.0$, $b{=}0.75$);
(iii)~VanillaRAG (BGE-small-en-v1.5, cosine, no novelties);
(iv)~\chatgit\,(N3+N4) (session memory + intent routing only).

\section{Discussion}
\label{sec:disc}

\paragraph{N5 drives measurable gain.}
Bidirectional call-neighbourhood augmentation (+4.2\% MRR,
+17.7\% EXPLAIN MRR) directly addresses the most common retrieval
failure: a function chunk without its caller/callee context is
incomplete. The proportional boost
($0.06\times s_\text{parent}$) is critical---an earlier fixed
$+0.05$ boost degraded performance by $9.7\%$ by injecting
low-confidence neighbours.

\paragraph{N1 and N2 on shallow-clone repositories.}
Both are neutral on this benchmark because test repos were
shallow-cloned (1 commit), providing no multi-commit volatility
signal for \nI and sparse call graphs for \nII. On full-history
production codebases, \nI provides strong differentiation: 67\% of
ConvCodeBench annotations target the top-20\% of files by commit
frequency.

\paragraph{HITS vs.\ PageRank.}
PageRank assigns one score per node; HITS separates orchestrators
(hubs: high out-relevance) from core utilities (authorities: high
in-relevance). For SUMMARIZE, hubs surface app factories and CLI
entry points; for LOCATE, authorities surface base classes and data
model definitions.

\paragraph{SUMMARIZE weakness: a dataset artefact.}
MRR collapses to 0.000 for SUMMARIZE because module-summary chunks
(the correct retrieval target) were excluded from the evaluation GT
set to reduce chunk count---making the answer unreachable for any
system. The live pipeline correctly generates and boosts these chunks.

\paragraph{Limitations.}
(1)~18 evaluation queries is small; we report bootstrap CIs and
effect sizes to mitigate.
(2)~Shallow clones prevent full N1/N2 measurement.
(3)~Llama-3.1-8b-instant introduces generation variance; retrieval
metrics are model-agnostic.

\section{Conclusion}
\label{sec:conclusion}

We presented \chatgit, a conversational code QA system with nine
individually-motivated novelties addressing fundamental limitations
of commercial tools and academic baselines.
Starting from a keyword-search baseline (F1\,=\,0.60), the system
reaches \textbf{F1\,=\,0.88} (+47\%) on an in-house query suite,
\textbf{MRR\,=\,0.389} on ConvCodeBench ($3.7\times$ BM25,
$p{=}0.013$, large effect), and maintains \textbf{zero cross-turn
redundancy} throughout all multi-turn conversations.

\paragraph{Future work.}
Neural coreference resolution; training the intent classifier on
ConvCodeBench; hybrid BM25+dense retrieval; Rust/C\#/Kotlin support;
VS Code integration; prospective user study; incorporating HITS scores
as live retrieval signals on full-history repositories.
