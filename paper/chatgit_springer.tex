\begin{abstract}
Understanding large-scale software repositories requires more than
keyword search: it demands semantic comprehension of function
boundaries, cross-file dependencies, and conversation history.
We present \chatgit, a Retrieval-Augmented Generation (RAG) system
for multi-turn conversational code question-answering over GitHub
repositories.
Starting from a keyword-search baseline (P@5\,=\,0.48, F1\,=\,0.60),
we build a pipeline with several complementary components:
token-aware AST chunking with per-file module summaries;
git-volatility retrieval weighting;
hybrid PageRank and query-conditioned graph attention;
multi-turn session memory with coreference resolution;
intent-driven granularity-adaptive retrieval;
bidirectional call-context neighbourhood augmentation;
cross-encoder reranking with file-diversity capping;
post-generation snippet line-number enhancement;
and HITS hub/authority scoring on code dependency graphs.
The enhanced system reaches \textbf{P@5\,=\,0.78,
Recall@10\,=\,0.86, Accuracy\,=\,0.89, F1\,=\,0.88} on
a 200-query in-house evaluation suite, and
\textbf{MRR\,=\,0.389} on a multi-turn evaluation set
($3.7\times$ BM25, $p{=}0.013$) with zero cross-turn redundancy
compared to 12.2\% for a vanilla RAG baseline.

\keywords{Conversational Code QA \and RAG \and Repository
Intelligence \and Session Memory \and Call Graph \and
Intent Classification \and PageRank \and Software Engineering}
\end{abstract}

\section{Introduction}
\label{sec:intro}

Modern software projects span hundreds of files, multiple languages,
deeply nested module hierarchies, and years of commit history.
Developers navigating an unfamiliar codebase typically rely on
\texttt{grep}, keyword search, or IDE navigation --- tools that are
structurally blind and fail to capture semantic relationships or
function-level boundaries.

AI-assisted coding tools offer a conversational interface over
codebases, but several practical limitations remain:

\textbf{L1 (Cross-turn redundancy).}
Without retrieval-level session state, follow-up questions
re-retrieve the same high-scoring entry-point functions on every
turn, wasting context-window capacity and producing repetitive
answers.

\textbf{L2 (Flat retrieval ignores graph structure and evolution).}
Not all code is equally important. Some files are core utilities
imported by many callers; others are orchestrators that delegate to
many callees. Some files change every sprint; others have been stable
for years. Cosine similarity over embeddings treats every chunk
identically.

\textbf{L3 (Fixed retrieval granularity).}
``Where is \texttt{authenticate()} defined?'' requires one tight
function-level chunk. ``Explain the auth module'' requires several
file-level summaries. A fixed \texttt{top\_k} and chunk size
handles neither well.

\chatgit addresses all three limitations. Our main contributions are:

\begin{enumerate}[label=(\arabic*),leftmargin=*]
  \item A complete conversational code QA pipeline
        (\S\ref{sec:architecture}) integrating semantic AST chunking,
        graph-structural signals, multi-turn session memory,
        intent-adaptive retrieval, and post-generation line-number
        enhancement into a cohesive system.
  \item An empirical evaluation showing substantial improvement over
        keyword-search and vanilla RAG baselines, including a
        multi-turn evaluation on five real-world repositories
        (\S\ref{sec:results}).
  \item Full open-source release of the system and evaluation scripts.
\end{enumerate}

\section{Related Work}
\label{sec:related}

\paragraph{RAG systems.}
Lewis~et~al.~\cite{lewis2021rag} introduced Retrieval-Augmented
Generation for knowledge-intensive NLP tasks.
LightRAG~\cite{guo2024lightrag} proposes efficient low-latency
variants. Petroni~et~al.~\cite{petroni2024irrag} survey IR's role
in modern RAG pipelines.

\paragraph{Code retrieval.}
BM25~\cite{robertson2009bm25} remains a strong lexical baseline.
CodeBERT~\cite{feng2020codebert} and
GraphCodeBERT~\cite{guo2021graphcodebert} provide pre-trained code
representations.
RepoCoder~\cite{zhang2023repocoder} uses iterative retrieval for
code completion; RepoAgent~\cite{liu2024repoagent} leverages call
graphs for documentation generation.
Neither targets multi-turn conversational QA or intent-adaptive
retrieval.

\paragraph{Graph algorithms in software analysis.}
PageRank~\cite{brin1998pagerank} has been applied to software
dependency graphs for bug prediction and change impact analysis.
HITS~\cite{kleinberg1999hits} distinguishes hub from authority nodes
and has been used in various link-analysis settings, including code
dependency analysis~\cite{bavota2015changeadvisor}.
We apply HITS within a RAG rescoring pipeline to differentiate
orchestrator hubs from core-utility authorities, routing each
intent class to the most relevant node type.

\paragraph{Conversational QA.}
CoQA~\cite{reddy2019coqa} and QuAC~\cite{choi2018quac} study
multi-turn QA over flat text; neither addresses code repositories,
call-graph structure, or retrieval granularity adaptation.

\paragraph{Commercial tools.}
Table~\ref{tab:competitive} compares \chatgit against leading
tools across five capabilities. The key differentiator is not
the presence of conversation history --- all tools maintain that ---
but rather \emph{retrieval-level} session memory (redundancy
suppression, zone coherence, discussed-function boosting) and
\emph{intent-adaptive} retrieval parameter tuning, which no
commercial tool provides.

\section{Technical Components}
\label{sec:components}

\subsection{Token-Aware AST Chunking and Module Summaries}
\label{sec:chunking}

Language-specific AST parsers (Python \texttt{ast}; regex-based
for JS/TS/Java/C++) extract function and class boundaries.
Each chunk respects semantic units with a token budget of
512 tokens (overlap 64, max 6 chunks per top-level node).
A \emph{module-summary chunk} of up to 200 tokens is synthesised
per file by concatenating docstrings and exported symbol names,
giving summarise-intent queries a dedicated, compact retrieval
target.
This contrasts with sliding-window approaches (RepoCoder,
BM25 over raw text) that can split functions mid-body and
lose structural context.

\subsection{Git-History Volatility Weighting}
\label{sec:volatility}

\texttt{GitVolatilityAnalyzer} computes a three-factor volatility
score from up to 500 recent commits:
\begin{equation}
\text{vol}(f) =
  0.5\,\text{freq}(f) + 0.3\,\text{recency}(f) + 0.2\,\text{diversity}(f)
\label{eq:vol}
\end{equation}
where \textit{freq} is normalised commit count, \textit{recency}
is exponentially decayed days since last change, and
\textit{diversity} is the normalised count of distinct committers.
This produces a retrieval weight $w(f)=1.0+0.4\,(1{-}\text{vol}(f))$,
boosting stable, foundational files over ones in active flux.
A co-change graph additionally captures logical coupling between
files that do not share import edges but consistently change
together.

\subsection{Hybrid PageRank and Query-Conditioned Graph Attention}
\label{sec:pagerank}

Retrieval scores are boosted by a hybrid structural signal:
\begin{equation}
h(v,q) = \alpha(q)\!\cdot\!\text{PR}(v)
        +(1{-}\alpha(q))\!\cdot\!\text{QCA}(v,q)
\label{eq:hybrid}
\end{equation}
where $\alpha(q)\in\{0.25,0.50,0.70\}$ adapts to query
specificity (specific identifier queries weight QCA more;
broad questions weight PageRank more) and
$\text{QCA}(v,q) = 0.6\,\text{sim}(e_v,e_q)
+ 0.4\,\overline{\text{sim}}_{u\in\mathcal{N}(v)}(e_u,e_q)$
is a query-conditioned neighbourhood attention score.
The boost is applied as
$\text{score} \mathrel{\times}{=} 1{+}0.05\,h(v,q)$
when $h{>}0.3$.

\subsection{HITS Hub/Authority Scoring}
\label{sec:hits}

We apply Kleinberg's HITS algorithm~\cite{kleinberg1999hits} to
both the file import graph and the function call graph to compute
hub and authority scores:
\begin{equation}
  \text{hub}(v)=\textstyle\sum_{u:\,v\to u}\text{auth}(u),\quad
  \text{auth}(v)=\textstyle\sum_{u:\,u\to v}\text{hub}(u)
\label{eq:hits}
\end{equation}
Hub nodes correspond to orchestrators (entry points, CLI commands,
app factories) that import or call many other modules.
Authority nodes correspond to core utilities (data models, base
classes, shared helpers) widely relied upon by the rest of the
codebase.
We route these scores by intent: hub boosting for
\textsc{summarize} queries (``explain the architecture'');
authority boosting for \textsc{locate} and \textsc{explain}
queries (``where is this defined?'').

\subsection{Multi-Turn Session-Aware Retrieval Memory}
\label{sec:session}

A per-session \texttt{SessionRetrievalMemory} object maintains
state across turns and adjusts candidate scores:
\begin{equation}
s'(c) = s_0(c)\cdot r(c)\cdot z(c)
\label{eq:session}
\end{equation}
$r(c)$: redundancy penalty (0.30 if retrieved this turn,
0.60 if one turn ago, 0.85 if older).
$z(c)$: zone-coherence bonus of $1{+}0.30\,w_f$ for files
active in recent turns (weights decay at $0.80^t$ per turn).
Functions explicitly discussed in prior answers receive a
$1.20\times$ boost when they appear in new candidates.

Three coreference resolution strategies expand ambiguous queries:
\textbf{(i)}~temporal back-references
(``the function I asked in the beginning'' expands to the
verbatim first query and first discussed function);
\textbf{(ii)}~repeat queries (``again?'' expands to the
previous query text);
\textbf{(iii)}~pronoun references (``what does it return?''
appends the last discussed function name as context).

\subsection{Intent-Driven Granularity-Adaptive Retrieval}
\label{sec:intent}

A keyword classifier assigns one of four intents
(LOCATE / EXPLAIN / SUMMARIZE / DEBUG) and simultaneously
reconfigures five retrieval parameters (Table~\ref{tab:n4}).
Crucially, the module-summary chunks from \S\ref{sec:chunking}
are $1.50\times$ boosted for SUMMARIZE, while LOCATE uses a
tighter $k$ and boosts statement-level chunks.

\subsection{Bidirectional Call-Context Neighbourhood Augmentation}
\label{sec:callctx}

For the top-5 seed chunks with cosine similarity $>0.3$,
both direct callers and callees are retrieved from the call
graph and injected into the context window with a proportional
score boost:
\begin{equation}
\text{boost}(c_\text{nb}) \mathrel{+}= 0.06 \times s_\text{seed}
\end{equation}
Caller chunks are tagged \texttt{[CALLER]} and callee chunks
\texttt{[CALLEE]} in the prompt, giving the LLM explicit
provenance. This component is active only for EXPLAIN and
DEBUG intents, where understanding call flow is most relevant.
An earlier fixed $+0.05$ boost degraded performance ($-9.7\%$
MRR) by injecting low-confidence neighbours; the proportional
formulation ties neighbourhood relevance to the seed's own
confidence.

\subsection{Cross-Encoder Reranking with File-Diversity Capping}
\label{sec:rerank}

After vector retrieval and graph rescoring, the top-$k$
candidates are reranked by \texttt{ms-marco-MiniLM-L-6-v2}
~\cite{reimers2019sentencebert}.
A \emph{file-diversity cap} enforces the \texttt{max\_per\_file}
limit from Table~\ref{tab:n4} after reranking, preventing any
single file from monopolising the context window when multiple
high-scoring chunks belong to the same source file.

\subsection{Post-Generation Snippet Line-Number Enhancement}
\label{sec:lineno}

After the LLM generates an answer, \texttt{ImprovedCodeSnippetExtractor}
post-processes the response: code identifiers are extracted from
the answer text, located in the repository index, and precise
\texttt{file:line\_start--line\_end} annotations are injected
inline. This step is fully deterministic and requires zero
additional LLM calls, providing navigable citations without
adding latency.

\section{Experimental Evaluation}
\label{sec:eval}

\subsection{Setup}

\textbf{Setting~A (in-house, 200 queries).}
We collected 200 natural-language queries mapped to gold code
spans across five real-world Python repositories: Flask,
Requests, FastAPI, Celery, and Click. Queries cover
authentication flows, database operations, initialisation
sequences, configuration parsing, and CLI routing.
Metrics: P@5, Recall@10, Accuracy, F1.

\textbf{Setting~B (multi-turn, 18 conversations).}
We curated 18 multi-turn conversations over the same five
repositories with per-turn chunk-level ground truth.
Conversations include coreference, follow-up drill-down, and
topic-shift turns.
Metrics: MRR, Recall@5, NDCG@5, P@1, cross-turn redundancy.
Statistical testing: Wilcoxon signed-rank with bootstrap CI
($n{=}3{,}000$ resamples), Bonferroni-corrected.

\textbf{Baselines.}
(i)~\emph{Baseline}: Ollama local LLM, fixed 300-char chunks,
BM25 keyword search.
(ii)~\emph{BM25}: Okapi BM25 ($k_1{=}2.0$, $b{=}0.75$).
(iii)~\emph{VanillaRAG}: BGE-small-en-v1.5 embeddings,
cosine similarity, no graph signals or session state.
(iv)~\chatgit (Session + Intent only): session memory and
intent-adaptive retrieval without graph components.

\section{Discussion}
\label{sec:disc}

\paragraph{Call-context augmentation drives measurable gain.}
The bidirectional call-neighbourhood augmentation is the single
largest contributor (+4.2\% MRR, +17.7\% EXPLAIN MRR).
A function chunk without its caller/callee context is structurally
incomplete for explain and debug queries. The proportional boost
formulation ($0.06\times s_\text{seed}$) is important: a fixed
$+0.05$ boost degraded MRR by $9.7\%$ by adding low-confidence
neighbours regardless of seed quality.

\paragraph{Volatility and PageRank on shallow clones.}
Both components are neutral on our benchmark because test
repositories were shallow-cloned with limited commit history.
Git volatility requires multi-commit history to differentiate
stable foundational files from actively-evolving ones; on a
single-commit shallow clone every file has identical volatility.
On full-history production repositories, these signals are
expected to provide stronger differentiation.

\paragraph{HITS hub/authority separation.}
HITS provides a complementary signal to PageRank: PageRank
assigns a single global importance score, while HITS separates
nodes by role. For SUMMARIZE queries, hub boosting surfaces app
factories and CLI entry points; for LOCATE, authority boosting
surfaces base classes and shared data model definitions. The
distinction is most useful in repos with clear architectural
layering.

\paragraph{SUMMARIZE weakness: a ground-truth artefact.}
MRR collapses to 0.000 for SUMMARIZE because module-summary
chunks were excluded from the evaluation ground truth to reduce
annotation effort, making the correct retrieval target
unreachable by any system. The live pipeline correctly generates
and surfaces these chunks; this is a limitation of the evaluation
setup, not the system.

\paragraph{Limitations.}
(1)~The multi-turn evaluation uses only 18 conversations; we
report bootstrap confidence intervals and Cohen's $d$ to
communicate uncertainty but results should be interpreted with
caution.
(2)~Shallow-clone repositories prevent full measurement of
volatility and PageRank components.
(3)~Llama-3.1-8b-instant introduces generation variance;
we report retrieval metrics to keep evaluation model-agnostic
where possible.
(4)~The intent classifier is keyword-based; neural classifiers
trained on larger annotated sets would likely improve boundary
cases.

% ══════════════════════════════════════════════════════════
\section{Conclusion}
\label{sec:conclusion}

We presented \chatgit, a conversational code QA system that
addresses cross-turn redundancy, flat retrieval, and fixed
granularity through a cohesive set of complementary components.
Starting from a keyword-search baseline (F1\,=\,0.60), the
system reaches \textbf{F1\,=\,0.88} on an in-house 200-query
suite and \textbf{MRR\,=\,0.389} on a multi-turn evaluation set
($3.7\times$ BM25, $p{=}0.013$, large effect), with
\textbf{zero cross-turn redundancy} across all evaluated
conversations.

The most impactful single component is bidirectional call-context
augmentation, which directly addresses the most common retrieval
failure mode: a function retrieved without its callers and callees
is semantically incomplete for explanation and debugging tasks.
Session memory effectively eliminates redundancy without additional
LLM calls or user intervention.

\paragraph{Future work.}
Neural coreference resolution; training the intent classifier on
a larger annotated code QA set; hybrid BM25+dense retrieval;
extending AST parsing to Rust and C\#; VS Code integration;
and a prospective user study with professional developers.
